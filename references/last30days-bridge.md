# last30days 原生社区协作

仅当用户明确要求使用 last30days，或需要平台原生帖子、评论、字幕及互动数据时读取。普通雷达默认走宿主网页检索；更新雷达技能本身不触发社区研究、引擎 setup 或来源健康检查。

## 找到实际安装与入口

从宿主技能目录或用户给出的路径读取实际 `last30days/SKILL.md`，将其所在目录作为根目录，不假设仓库内还有副本。方法参考本地评估过的 v3.27.1；实际调用以当时安装的根说明与相关 references 为准，不复制其脚本、依赖、信源配置或缓存。

执行引擎前遵循其根入口的条件读取：runtime、research-runbook，以及本次涉及的 setup、agent-mode 或 followups。确认安装、解释器、当前 CLI 和副作用；Windows 用 PowerShell 与已核验的解释器路径，按脚本的实际参数传值，不直接粘贴 Bash 示例。Python 3.12+ 是该版本引擎的要求，雷达离线助手没有因此新增同样的版本门槛。

运行时或安装缺失不授权安装、读取浏览器 cookie、改凭证或更改全局设置。用户已给的有效授权继续适用；不重复请求。引擎硬性前置条件无法满足时说明该部分未完成。可交付已独立核验的原文，但不能称 last30days 已运行或原生平台已覆盖；用户指定必须使用引擎时，不能以网页报告冒充完成。

## 计划、执行与来源状态

按原技能的 `--diagnose` 和适用的 doctor 流程确定可用来源；配置预测与本次 `source_status` 分开。X 不可用时按引擎规则继续可用来源，不把缺失来源写成零讨论，也不自动开通平台。

实体与账号／仓库核对后，Agent 根据其当前 runbook 编写单独的引擎计划，使用其 `intent`、`freshness_mode`、`cluster_mode`、`subqueries` 格式。本雷达的 `plan_search.py` JSON 是宿主网页计划，**不能直接作为引擎 `--plan`**。按当前版本处理适用来源、定向参数与日期限制，不猜测参数；命名实体保留实体锚点。不要为了多平台覆盖引入与安全问题无关的市场赔率、购物评价或广告材料。

临时计划写到宿主允许的本任务临时目录；内容通过文件传递，不把 JSON 或帖子文本拼进 shell 命令。原始结果的保存位置需通过引擎当前受信解析规则明确指定本任务临时目录，捕获一次并复用；检查其他缓存／配置写入是否在宿主许可范围。用户要求保留雷达时再按主入口保存最终报告，不改全局默认目录。

遵循引擎的实际运行与返回契约。仅以成功返回的数据声称运行；保存路径必须确实存在。记录原生来源与宿主补搜各自的查询、读取和结果状态，保留实际 `Partial Coverage`／`Report.source_status`；若输出要求传递引擎 footer，使用其实际返回块，不重建数字、来源或路径。引擎失败只停止依赖该数据的结论，已授权的原文核验仍可推进。

## 转为安全雷达证据

引擎聚类是发现候选，平台数与互动数是传播信号。回原报告、维护者公告、修复记录或论文核验实体、日期、攻击条件和实际效果；安全主张按雷达证据标准综合。跨平台转述同一实验不会增加独立核验，官方身份也不会自动提高技术证据等级。

`Nothing solid this window` 表示本轮社区候选未达相关性门槛；不引用被拒绝的候选来凑事件或评论。窗口外 library 材料标为历史背景。可用实际打开的宿主原文补充事件，同时说明原生社区证据不足。

平台原作者披露可作一手线索，维护者回复可支持其明确说明的版本或修复；用户评论只支持该用户的自述。保留返回的真实帖子、评论、PR 或视频链接，引用字幕时标时间点及已读范围。最终按用户要求的中文雷达／增量格式交付，事实、传播和建议分开。

定点核实、缓存深挖或重排已有研究时使用当前原技能的对应路线，不为一次改写重新 setup 或全量研究。不把本地笔记、基准报告或客户信息作为 corpus 上传或远程提示；候选选题不自动写进其持久队列。
