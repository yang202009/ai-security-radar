# 研究复用与事件增量

用于已有雷达的解释、改写、定点核实、深挖，以及“与上次相比／只看新增”。新主题仍走主入口的新研究流程。

## 先选择最小研究范围

| 请求 | 执行 |
|---|---|
| 解释已有机制、压缩报告、改成客户版／技术版／选题版 | 复用已有证据，保留窗口与核验截止；不把改写日期当新的核验日期 |
| “现在修了吗”“这个数字还有效吗” | 打开该主张的最新原文、公告或版本记录，只核实所问事实；修复和真实利用分别查 |
| 深挖第 N 条／某机制 | 复用该事件材料，定向补前提、版本、权限、方法、反例与修复缺口；不重跑全领域 |
| 与上次比较、只看新增 | 找基准报告，研究所需窗口，按下述变化类别对照 |

当前性主张需要新核验，不能因已有材料就回答“仍然有效”。请求既含解释又含当前性时先解释已知事实，再补当前状态，并标明各自截止时间。

优先基准是用户指定文件，其次是本对话中最近的同主题报告；需要找保存记录时仅在 用户指定的报告目录（无约定时为工作区 `reports/`） 内按雷达名称和主题检索。采用已有基准时说明文件和截止时间，不扫描整个工作区。没有基准时可给首次研究，明确“无法判断相较上次的新增”；用户只要精确差异时等待其指定基准，同时完成不依赖基准的原文核验。

## 对照事件与变化

用产品形态、原始披露／CVE 和机制匹配事件。标题相似不足以合并；不同产品的独立披露也不因机制相同而去重。同一原始研究的新转载只增加传播记录。

- **新增**：基准中没有该事件，且本窗口内有首次原始披露。以前遗漏的旧事件注明“补充背景”，不能冒充新发生。
- **实质更新**：已有事件出现新受影响版本、实际利用证据、修复、绕过或控制效果变化。给出上次状态、新事实、更新日期和直达证据。
- **更正**：新材料纠正已有范围、归因、效果或日期。说明原判断、新判断和冲突依据；原报告保留，修订另存或按用户授权更新。
- **重复／无实质变化**：只有标题、转载或自动刷新日期变化，通常省略正文，覆盖记录注明。
- **背景／待核**：窗口外、日期不明、正文受限或关键冲突未解。与入选事件分开。

没有实质变化是有效结果。写“在本次已检查的材料中未确认新增／更新”，附覆盖缺口；不能推广为“没有攻击”或“产品安全”。所谓“升温／加速／攻击增加”要有可比的历史窗口、同类数据与取样条件，两次列表长度不同不构成增长证据。

## 本地复用与交付

本地报告、笔记和客户材料只作离线背景。构造远程查询时仅使用公开产品名、CVE 和攻击术语；不把本地正文、路径或客户信息传给检索、原生社区引擎或重排服务。

增量报告先给新增／实质更新／更正，保留基准链接、双方截止时间和变化证据。解释／改写沿用原有引用；定点核实给已确认变化及未查清部分，不强制生成完整日报。要求保存时遵循主入口的输出位置、frontmatter 与不覆盖旧报告规则。

候选选题仅说明可写什么及缺少哪些证据。实际发布成功并按仓库流程确认前，不标记已发布、不写发布登记；提醒与持久内容队列按用户明确请求处理。
